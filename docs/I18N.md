# UI Internationalization (i18n)

> Vietnamese (`vi`) and English (`en`) for all UI-owned strings.

## Decision: custom catalogs (not i18next)

The app already ships ~2,500 matched translation keys with:

- `useT()` / `t()` in the renderer
- `npm run lint:i18n` parity gate (`vi` ↔ `en`)
- Nested key paths (`nav.dashboard`, `settings.uiLocaleLabel`, …)

Migrating to `i18next` / `react-i18next` would add bundle weight and a large mechanical churn without improving coverage. **We keep the existing lightweight catalog** and strengthen persistence + first-run flow.

## Locale file layout

```
src/renderer/i18n/
  index.ts              # useT(), applyUiLanguageStatus()
  locales/
    vi/index.ts         # Vietnamese catalog (source of truth shape)
    en/index.ts         # English catalog (must match vi keys)
  ui-locale-catalog.ts
  status.ts, errors.ts, enums.ts
```

Do **not** translate user novel text, provider output, or imported content — UI strings only.

## Source of truth: SQLite `app_meta`

| Key | Value |
|-----|--------|
| `settings.ui.language` | `system` \| `vi` \| `en` |
| `settings.ui.language.chosen` | `1` when user completed first-run or settings pick |

Legacy keys `khepree.locale.*` are migrated on read.

**Not used for persistence:** `localStorage`, Zustand persist, renderer-only storage.

Service: `src/main/services/ui-language-service.ts`  
IPC: `uiLanguage:get`, `uiLanguage:set`, `uiLanguage:completeFirstRun`

## First launch after Squirrel install

**Installer:** Electron Forge **Squirrel** — no custom NSIS language wizard.

**Product requirement:** “First launch immediately after installation language selection.”

**Implementation:** On first app open (fresh DB, no projects, setup not explored), show `LanguageFirstRunPage` **before** Khepree login and before functional workspace. Bilingual static copy on that screen (locale not chosen yet).

**Existing users upgrading:** If DB has projects or setup progress but no `settings.ui.language.chosen`, auto-set language from OS locale (`app.getLocale()`), mark chosen, **skip** blocking chooser — no data loss.

## Runtime switch

Settings → Language → Tiếng Việt / English / System.

Changes call `uiLanguage:set` → updates `app_meta` → `applyUiLanguageStatus()` → React re-renders with new catalog.

Electron native file dialogs use OS language; no custom application menu bar today.

## Adding strings

1. Add key to `locales/vi/index.ts`
2. Add same key path to `locales/en/index.ts`
3. Run `npm run lint:i18n`
4. Use `const t = useT(); t('your.key')` in components
